# راهنمای سئوی چندبوم

## اصلاحات این بسته
- فایل‌های `public/robots.txt` و `public/sitemap.xml` اضافه شده‌اند؛ Vite آن‌ها را هنگام build به ریشه خروجی منتقل می‌کند.
- متادیتای اولیه و Open Graph در `index.html` موجود است؛ محتوای SPA به‌تنهایی تضمین‌کننده رندر HTML اختصاصی برای هر URL نیست.
- متادیتای تب‌ها در `src/utils/seo.ts` تنظیم می‌شود؛ این کار برای ربات‌هایی که JavaScript اجرا نمی‌کنند جایگزین SSR/SSG نیست.

## کارهای لازم برای رتبه‌گیری بهتر
1. برای صفحات عمومیِ واقعاً مستقل و مقالات، SSR/SSG (مثلاً مهاجرت تدریجی به framework دارای رندر سرور) یا prerender معتبر پیاده کنید؛ URLهای هر مقاله باید HTML اولیه، title، description، canonical و JSON-LD اختصاصی داشته باشند.
2. فقط URLهای عمومی و قابل ایندکس را در sitemap نگه دارید. صفحات خصوصی را با احراز هویت امن کنید؛ `robots.txt` ابزار امنیت نیست و صرفاً crawling را راهنمایی می‌کند.
3. در Google Search Console مالکیت دامنه را تأیید کنید، sitemap را ارسال کنید و گزارش‌های Page Indexing و Core Web Vitals را هفتگی بررسی کنید.
4. برای مقاله‌ها محتوای اصیل و عمیق با نویسنده، تاریخ انتشار/به‌روزرسانی، منابع معتبر، لینک داخلی به قابلیت مرتبط محصول و CTA طبیعی بنویسید؛ از تولید انبوه متن کم‌ارزش و تکراری پرهیز کنید.
5. برای تصاویر نام توصیفی، alt فارسی دقیق، ابعاد مشخص و WebP/AVIF استفاده کنید. فونت‌ها را محلی و با `font-display: swap` بارگذاری کنید.
6. داده ساختاریافته را فقط وقتی اضافه کنید که با محتوای قابل مشاهده صفحه مطابقت داشته باشد. برای مقالات از `Article`/`BlogPosting`، برای breadcrumb از `BreadcrumbList` و برای محصول از `SoftwareApplication` در صورت انطباق استفاده کنید.
7. ریدایرکت‌ها، canonicalها، صفحات 404 واقعی، نسخه موبایل، دسترس‌پذیری و سرعت را با ابزارهای Search Console، Lighthouse و PageSpeed Insights بررسی کنید.

## نکته درباره sitemap
در حال حاضر فقط صفحه اصلی در sitemap درج شده چون فهرست تأییدشده‌ای از URLهای عمومی مقاله در سورس در دسترس نبود. پس از ایجاد مسیرهای عمومی واقعی، آن‌ها را به sitemap اضافه کنید؛ URL ساختگی یا صفحات خصوصی را اضافه نکنید.
