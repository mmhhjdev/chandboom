# راهنمای تغییرات بخش دنگ چندبوم

## تغییرات این نسخه
- اضافه شدن پنل جست‌وجوی کاربران بر اساس نام کاربری، ارسال دعوت، نمایش اعضا و پاسخ به دعوت‌ها.
- نمایش نام کاربری در نمای اصلی دنگ و امکان کپی آن.
- ثبت عضویت مالک پس از ساخت گروه با RPC سمت سرور.
- اعتبارسنجی مبلغ هزینه‌ها و بررسی انتخاب مصرف‌کننده برای هر ردیف فاکتور.
- اضافه شدن Migration افزایشی برای پروفایل‌ها، نام کاربری دائمی، عضویت‌ها، دعوت‌ها، توابع RPC و سیاست‌های RLS.

## ترتیب اجرا
1. از دیتابیس Supabase خود نسخه پشتیبان بگیرید.
2. در Supabase SQL Editor فایل `supabase/migrations/20261030_dong_collaboration.sql` یا نسخه مستقل `supabase/dong_collaboration.sql` را اجرا کنید؛ فقط یکی از این دو فایل لازم است.
3. در صورت بروز خطای مربوط به نام ستون/ساختار جدول، اجرای فایل را متوقف کنید و ابتدا ساختار واقعی `dong_groups`, `dong_expenses` و جدول `users` را تطبیق دهید؛ فایل برای ساختارهای متداول این پروژه به‌صورت افزایشی نوشته شده اما در این محیط به دیتابیس زنده متصل نشده است.
4. سپس پروژه را با `npm install` و `npm run build` بررسی کنید.

## نکات مهم
- نام کاربری به‌صورت سمت‌سرور ساخته می‌شود و تغییر آن توسط Trigger رد می‌شود.
- پروفایل فقط شامل شناسه، نام کاربری و نام نمایشی است؛ ایمیل و اطلاعات مالی در جست‌وجو برگردانده نمی‌شود.
- جست‌وجو به ۲۰ درخواست در دقیقه برای هر کاربر محدود شده است.
- پذیرش دعوت در تابع دیتابیس انجام می‌شود و عضویت تکراری با کلید یکتا کنترل می‌شود.
- این محیط به دیتابیس زنده دسترسی نداشته است. اجرای SQL روی دیتابیس واقعی و تست end-to-end انجام نشده است.
- فایل `dist/` پروژه اصلی بازسازی نشده است، چون نصب وابستگی‌ها در این محیط به پایان نرسید. برای انتشار نسخه جدید، Build را در محیط دارای وابستگی‌ها اجرا کنید و خروجی `dist/` را جایگزین نسخه قبلی کنید.
