# امنیت و سئوی چندبوم: آنچه تغییر کرد و آنچه باید خارج از ریپو انجام شود

## تغییرات این نسخه

**سئو**
- هر صفحه عمومی و هر مقاله فایل HTML مخصوص خودش را دارد (عنوان، توضیحات، canonical، Open Graph، Twitter و JSON-LD). قبلاً فقط مقالات این را داشتند و بقیه صفحات با یک عنوان یکسان به کراولر می‌رسیدند.
- `sitemap.xml` از همان فهرست صفحات ساخته می‌شود، پس دیگر آدرس‌های ناموجود (مثل `/dashboard`) ندارد.
- تصاویر OG که در `public/` نبودند برگردانده شد. مقالات از تصویر JPG استفاده می‌کنند، چون پلتفرم‌های اجتماعی SVG را نشان نمی‌دهند.
- `hreflang` به نسخه‌ی انگلیسی که وجود نداشت حذف شد.
- `base` ویت از `./` به `/` تغییر کرد. قبلاً اسکریپت صفحات مقاله‌ها با مسیر نسبی بارگذاری نمی‌شد.
- Google Analytics فقط یک بار و از مسیر کد بارگذاری می‌شود.
- یک `<noscript>` با لینک‌های داخلی اضافه شد تا ربات‌های بدون JS هم مسیر صفحات را ببینند.

**امنیت**
- Content-Security-Policy در بیلد تولید اضافه می‌شود (در حالت dev نه، چون Vite برای Fast Refresh از اسکریپت inline استفاده می‌کند).
- اسکریپت inline ریدایرکت SPA به `public/js/spa-redirect.js` منتقل شد تا CSP بتواند inline را ممنوع کند.
- فایل `public/_headers` شامل CSP کامل، HSTS، X-Frame-Options، Referrer-Policy، Permissions-Policy (میکروفون فقط برای خود سایت) و COOP است.
- بررسی شد: هیچ `dangerouslySetInnerHTML`، `innerHTML` یا `eval` در کد وجود ندارد و همه‌ی لینک‌های `_blank` دارای `noopener` هستند.

## کارهایی که خارج از ریپو باید انجام دهید

1. **Google Search Console:** دامنه را تایید کنید و `https://chandboom.ir/sitemap.xml` را ثبت کنید. گزارش Coverage را هر هفته بررسی کنید.
2. **Bing Webmaster Tools:** همان sitemap را ثبت کنید.
3. **هدرهای امنیتی روی GitHub Pages:** GitHub Pages فایل `_headers` را نمی‌خواند. اگر DNS دامنه را به Cloudflare ببرید (پروکسی فعال)، می‌توانید هدرها را با Transform Rules اعمال کنید. یا میزبانی را به Cloudflare Pages یا Netlify ببرید که `_headers` را مستقیم می‌خواند.
4. **HSTS preload:** بعد از اطمینان از HTTPS در همه‌ی زیردامنه‌ها، دامنه را در hstspreload.org ثبت کنید.
5. **تست نهایی:** با Google Rich Results Test، Facebook Sharing Debugger، و Lighthouse (بخش SEO و Best Practices) بررسی کنید.

## پیشنهادهای بعدی (اولویت‌بندی‌شده)

**سئو**
- **Prerender کامل محتوا:** الان فقط meta و لینک‌ها در HTML ثابت هستند. متن صفحات امکانات، تعرفه و مقالات را هم با `react-dom/server` در بیلد بنویسید تا کراولرها محتوا را ببینند.
- **تاریخ واقعی مقالات:** فیلد `publishedAt` و `updatedAt` به هر مقاله اضافه شود. الان همه‌ی مقالات تاریخ ثابت `2026-10-30` دارند.
- **تصاویر PNG برای مقالات:** برای هر مقاله یک تصویر OG اختصاصی (1200×630) بسازید. SVG فعلی فقط برای نمایش داخل صفحه مناسب است.
- **مقالات بیشتر با کلمات کلیدی فارسی:** مثلاً «بهترین اپ مدیریت مالی شخصی»، «ثبت خودکار پیامک بانکی»، «نحوه تقسیم هزینه سفر». هر مقاله باید یک پرسش مشخص را جواب دهد.
- **Schema FAQ:** برای صفحه‌ی سوالات متداول، JSON-LD از نوع `FAQPage` اضافه کنید تا در نتایج گوگل نمایش داده شود.
- **Internal linking:** از هر مقاله به صفحه‌ی امکانات مرتبط و از صفحه‌ی امکانات به مقاله‌های مرتبط لینک بدهید.

**امنیت**
- **Trusted Types و حذف `'unsafe-inline'` از style:** React از inline style استفاده می‌کند. با انتقال به CSS modules یا کلاس‌های Tailwind می‌توان آن را حذف کرد.
- **گزارش CSP:** یک endpoint برای `report-uri` یا `report-to` تعریف کنید تا خطاهای CSP را در تولید ببینید قبل از اینکه کاربری گیر کند.
- **MFA برای ادمین:** ورود ادمین را فقط با Supabase Auth و MFA (TOTP) انجام دهید. session ادمین در localStorage نباید ۲۴ ساعته باشد.
- **Rate limiting ورود و OTP:** در Supabase Auth محدودیت نرخ تنظیم کنید و CAPTCHA (Turnstile) را برای فرم‌های عمومی اضافه کنید.
- **Dependency audit در CI:** `bun audit` یا Dependabot را فعال کنید.
- **حذف `sanitizeHtml` بی‌استفاده** یا جایگزینی با DOMPurify اگر روزی HTML کاربر نمایش داده شد.

**اعتماد و تبدیل (مناسب بازار ایران)**
- **نماد اعتماد الکترونیکی (ساماندهی):** برای افزایش اعتماد کاربران به پرداخت، نماد اعتماد را بگیرید و در فوتر نمایش دهید.
- **صفحه‌ی حریم خصوصی و قوانین:** صفحه‌ی مستقل با توضیح نگهداری داده‌های مالی و بانکی، و لینک آن در فوتر.
- **بنر رضایت کوکی:** با GA4 باید رضایت کاربر گرفته شود. یک بنر ساده با گزینه‌ی «فقط ضروری» اضافه کنید.
